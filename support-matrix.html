UiPath.CoreIpc — Cross-Language Support Matrix

Feature parity across the three first-party implementations of the CoreIpc wire protocol.
Repo root · Wire protocol: 5-byte binary frame header [1B type][4B LE u32 length] + JSON payload.

All three implementations speak the same wire protocol over the same transports: a C# reference that's been in production for years, a TypeScript/Node.js port that targets browsers as well as Node, and a newer Python port (async/asyncio). Each can act as either client or server and interoperate freely with the other two.

This table catalogues what each implementation actually ships in its current mainline. Where a feature is available in one language but not another, the cell explains the equivalent idiom (or why the gap exists).

1. Transports

Feature C# TypeScript Python
Named pipe ✓ System.IO.Pipes.NamedPipeServerStream + NamedPipeClientStream with PipeDirection.InOut, PipeOptions.Asynchronous, byte mode. Windows ACLs configurable via AccessControl delegate. ✓ Node only. net module connects to \\.\pipe\<name> on Windows. Browser build explicitly excludes this transport. ✓1 Cross-platform. Windows: asyncio ProactorEventLoop pipe APIs (create_pipe_connection, start_serving_pipe). Linux/macOS: AF_UNIX socket at $TMPDIR/CoreFxPipe_<name>, matching the path .NET and the TS port use on Unix.
TCP ✓ TcpListener / TcpClient with ConcurrentAccepts, retry on ConnectionRefused. ✗ Not implemented; TS clients use named pipe (Node) or WebSocket (both). ✗2 Dropped from Python v1 scope. The transport ABC in coreipc/transport/base.py is the only surface a future TCP module would touch.
WebSocket ✓ System.Net.WebSockets.ClientWebSocket + pluggable server Accept delegate; binary message type. WebSocketStream adapts to the Stream contract. ✓ Node: ws npm package. Browser: native WebSocket. Same codebase drives both via a thin Socket abstraction. later Deferred. Anticipated path: websockets package wrapped to expose (reader, writer) like the other transports.

2. RPC primitives

Feature C# TypeScript Python
Interface-as-contract ✓ Declare a C# interface. Endpoint name = typeof(T).Name. No code generation or attributes required. ✓ Decorated class: @ipc.$service + @ipc.$operation. Method bodies are stub throw void 0. Runtime reflection builds the proxy. ✓ @service on the class + @operation on each async method. Endpoint name = class name, matching C#.
Async request / response ✓ Task<T>-returning methods. Response Data = IpcJsonSerializer.Serialize(result). ✓ Promise<T>-returning methods. Each argument pre-stringified into the wire Parameters array. ✓ async def … -> T. Return type annotation drives result deserialization.
One-way (void) methods ✓ Task-returning methods are fire-and-forget: the server replies with empty Data immediately and continues the method in the background. ✓ Declared as Promise<void>; follows the same fire-and-forget dispatch as C#. ▪3 Python awaits async def … -> None before responding (simpler semantics; functionally equivalent for correct code).
Multiplexed concurrent calls ✓ ConcurrentDictionary<string, ManualResetValueTaskSource> tracks pending calls by Request.Id on each Connection. ✓ RpcChannel's outgoing-call table maps request id → PromiseCompletionSource. ✓ Connection._pending: dict[str, asyncio.Future]. Covered by test_concurrent_calls_on_single_connection.
Lazy connect + reuse ✓ ServiceClientProper.EnsureConnection reuses a live Connection; only the first call pays the handshake. ✓ ChannelManager keeps one connection per address; all proxies share it. ✓ IpcClient.get_proxy() is cheap; first real call opens the pipe via _LazyChannel.
Automatic reconnect ✓ Silent reconnect on the next call after a disconnect; existing pending requests fail fast. ✓ ChannelManager discards a broken channel and opens a new one on subsequent calls. later v1 raises on disconnect; caller retries. Straightforward to add in client.py.

5. Streams (large payloads)

Feature C# TypeScript Python
Upload stream (request payload + trailing bytes) ✓ MessageType.UploadRequest (=3). Request metadata then an 8-byte length prefix, then raw bytes streamed over the connection without buffering. ✗ TS port does not implement stream messages. ✗6 Out of scope for v1. The enum value is preserved; an incoming UploadRequest frame is rejected with UnsupportedMessageTypeError.
Download stream (response payload + trailing bytes) ✓ MessageType.DownloadResponse (=4). Symmetric to upload, for methods returning Stream. ✗ TS port does not implement stream messages. ✗6 Out of scope for v1; same rejection behaviour as UploadRequest.

Footnotes

  1. Named pipe — Python. Single class (NamedPipeClientTransport / NamedPipeServerTransport) that branches by platform: Windows uses asyncio's ProactorEventLoop pipe APIs (create_pipe_connection, start_serving_pipe); Linux/macOS uses an AF_UNIX socket whose path is computed as $TMPDIR/CoreFxPipe_<name> — the same convention .NET's NamedPipeServerStream uses on Unix and that the TS port mirrors in node/Platform.ts. Stale socket files are unlinked before bind. Path interop has been tested against the C# server; the same on-Linux path means a Python peer can talk to a TS or .NET peer with no translation.
  2. TCP — Python. Dropped from v1 at user request. Not hard to add: the transport ABC in transport/base.py is the only surface touched.
  3. One-way semantics. C# and TS dispatch Task/Promise<void>-returning methods fire-and-forget (respond with empty Data immediately, run the method in the background). Python awaits them before responding. Functionally equivalent for correct code; the difference matters only for benchmarking.
  4. TimeoutInSeconds enforcement. Emitted on the wire (so the server honours it), but the Python client doesn't yet start a local timer. The per-operation attribute in note 5 gives a more-ergonomic equivalent.
  5. Per-operation timeout attribute. @operation(timeout_seconds=5.0) sets Request.TimeoutInSeconds for that method. Pattern borrowed from GenericIPC's [RpcTimeout(5000)]. Neither the C# nor the TS port has this as an attribute; callers use Message.RequestTimeout instead.
  6. Streams. Defined in the C# MessageType enum (UploadRequest=3, DownloadResponse=4). Python v1 decodes the enum but rejects those two types with a clear UnsupportedMessageTypeError. TS has no stream support either.
  7. Tracing — C#/TS. Both have ILogger/logger-based diagnostics but no first-class per-call tracer object. Python's IpcTracer is modelled after GenericIPC's IRpcTracer and complements (rather than replaces) logging.
  8. Pluggable codec. The C# and TS implementations hard-bind to Newtonsoft-style JSON. Python factors the codec into a Codec ABC (wire/codec.py) so a future JSON-RPC 2.0, MessagePack, or other codec can be dropped in without touching transport, connection, or dispatch.
